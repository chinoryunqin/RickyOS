# 阅读触摸九宫格（2026-10-29）

## 调研与取舍

- KOReader 的 [InputContainer](https://koreader.rocks/doc/modules/ui.widget.container.inputcontainer.html) 用屏幕比例注册 tap/swipe 区域，旋转后重新计算区域。它的 [GestureDetector](https://koreader.rocks/doc/modules/device.gesturedetector.html) 区分 tap、hold、swipe，并在触摸完成时识别手势。
- [Custom Tap Zones 插件](https://github.com/ura23/customtapzones.koplugin) 支持 2×2 到 8×8 网格、逐格前翻/后翻/忽略，以及独立横竖屏配置。
- 本功能独立实现，不复制其他项目的源代码。先做固定 3×3 单击布局，五种动作：上一页、下一页、阅读菜单、全刷清屏、不响应。暂不增加多击等待或长按绑定，避免延迟正常翻页。

## 操作

- 设置 → 阅读 → 阅读触摸区域；阅读菜单 → 更多操作 → 阅读触摸区域。
- 默认关闭，保持原来的顶端菜单区和翻页分区。
- 点任意格子打开动作选择器。横屏、竖屏分别保存，旋转 180° 仍按当前看到的逻辑位置操作。
- 不区分左右手、不提供握持预设。直接点格子设动作；开启自定义会同时打开原有“触摸阅读控制”。
- 自定义格子中的“上一页/下一页”是明确动作，不再受惯用手、反向点击或书籍 RTL 设置二次反转；滑动仍按原有设置执行。
- 脚注/超链接优先于触摸分区，阅读工具栏/弹窗打开时由它们接管输入。顶部或边缘的滑动快捷方式、实体键均不变。
- 必须保留至少一个阅读菜单格，不能保存一个没有菜单入口的布局；编辑已损坏的文件时也会恢复中心菜单格。
- “恢复默认布局”只重置当前正在编辑的横屏或竖屏布局；关闭开关即恢复原有操作。原先滑动/惯用手配置不变。卡缺失时沿用现有设置系统的内存行为，本功能不新增内部存储写入。

## 代码与资源

`firmware/rickyos-plus-1.2/upstream/src/ReaderTapZones.h` 为无分配的坐标映射与预设，按逻辑宽高计算 `row * 3 + column`。端点使用半开区间，屏幕外坐标不触发动作；64-bit 乘法避免异常坐标溢出。配置增加 19 字节左右（一个 bool + 两组九字节）。不增加 framebuffer、网络任务或后台扫描。

`firmware/rickyos-plus-1.2/upstream/src/ReaderTapZonesJson.h` 使用设置 JSON 的 `readerTapZones` 对象（version=1，enabled，portrait[9]，landscape[9]）。未知版本、错误长度、负数、超范围、布尔动作或小数会回退关闭；旧文件缺字段也默认关闭。保存仍由现有 Settings.saveToFile 负责。

编辑 Activity 由现有活动栈持有，使用 `startActivityForResultWith` 的可失败分配；仅打开时存在，复用现有 OptionPopup（最多五个动作项）。渲染和点击共用一个 layout()；浮动工具与主页栏目留至少 6px 间距，九格是连续的真实屏幕分区。只读主循环发布的 MappedInputManager 快照，释放事件不重复 update；有初始按键/触摸释放屏障。

接入文件：ReaderUtils、EpubReaderActivity、SettingsActivity、阅读 More 菜单。TXT/Markdown/Kindle/微信读书通过现有 EPUB 阅读路径共享本配置。未支持的其他格式不声称获得新菜单动作。

主机编译另补 MainTabLayout 的显式 Rect 成员初始化，以及模拟器 HAL 的背部双击无事件接口；均是现有最新分支在 Clang/旧主机 HAL 上的兼容修正，不改变硬件按键逻辑。

## 最终交互修订（同日）

用户要求真实全屏映射，最终设置主页只保留总开关、竖屏触摸区和横屏触摸区两个独立入口。进入编辑后临时切换对应的 GfxRenderer 方向，退出、完成或 Activity 被替换时恢复调用者方向；不修改阅读方向设置。

编辑画布覆盖整个逻辑屏幕，不预留标题、状态栏或内边距。分界点取 ceil(width/3)、ceil(2*width/3) 与对应高度，点击直接调用生产 cellAt()，屏幕上看到的九格与阅读实际分区一致。连续划分是用户明确要求的触摸区域本身，因此九格之间不人为增加 6px 空白；设置主页栏目与浮动工具仍保留足够间距。底部“恢复默认布局”和“完成”是叠加的小工具，优先接管自身触摸，不缩小九格范围。复位仅改当前方向，最后菜单保护与即时保存不变。

编辑页不再提供横竖屏切换按钮，也不通过左右键切换配置。要换另一套布局，必须完成或返回设置主页，重新选入口。开启编辑时吞掉入口触摸的释放事件，避免同一次点按误开格子。

## 侧键翻页取消震动

用户确认高清修正版“现在没什么问题了”，并要求侧边按键翻页不震动。Plus 的原始反馈过滤在 `HalGPIO::updateHapticFeedback`，由主循环在业务处理前调用，之前包括两个物理侧键。现仅在当前前台 Activity 为 reader 时忽略 BTN_UP/BTN_DOWN 的震动触发；不消费按键、不改变翻页映射，按键方向与自定义绑定继续由 MappedInputManager 负责。触摸、Home、前面板键和总体反馈开关保留。菜单子 Activity 置于读者上方时不会因为堆栈仍有 reader 而静音其侧键。没有新增缓冲、堆池或后台任务。

实际 HAL 过滤器及前台判断的 ASan/UBSan 回归覆盖：两侧键阅读时不震动、触摸与侧键同时发生仍保留触摸反馈、Home/前键不受影响、菜单/无 Activity、全局禁用、长按和电源键排除；原有马达与 I2C/计时器故障测试通过。体验版本 `1.2.11-touchgrid-hd2`，沿用 hd1 的已确认墨色参数。

## 反馈开关最终修订（取代固定阅读静音）

用户改为要求「系统 → 按键」提供可选开关，并明确底部盖板按键没有键程，应由触控设置控制。实现为「触控震动」与「侧边键震动」两个独立偏好：

- FT6336 屏幕触摸、底部盖板 Previous/Next（SDK 报 BTN_LEFT/BTN_RIGHT）和电容 Home 沿用 `plusTouchFeedback`。
- AI/BOOT（GPIO61，BTN_CONFIRM）和扩展器侧边上/下（BTN_UP/BTN_DOWN）有键程，使用新增 `plusSideKeyFeedback`，默认 0。
- 按真实硬件来源过滤，不受逻辑映射、当前页面、横竖屏或翻页方向影响。开启侧键震动后读书翻页同样会震动；关闭不影响底部三键的触控反馈。
- 待机同时禁用两组；Power 不参与反馈。两组输入同帧到达最多发一次脉冲。
- 原先「阅读前台固定静音」及其 ActivityManager 查询已移除，不再覆盖用户设置。
- 设置文件新增数值键 `plusSideKeyFeedback`。缺失/非法值回退关闭，四种开关组合序列化、反序列化往返通过；恢复默认按键时触控=开、侧键=关。
- 按键菜单容量从 8 增至 9，避免新增选项挤占恢复默认行；复用现有开关行，无新增页面。关闭任一反馈项立即停止当前震动。
