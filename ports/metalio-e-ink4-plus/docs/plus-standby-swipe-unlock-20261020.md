# Plus 锁屏右滑解锁 · 2026-10-20

用户在批准网络修复发布后提出新增独立的锁屏滑动解锁开关，因此暂停发布，先纳入 Plus 1.2.4 候选。

## 依据与行为

- 修改前 `upstream/src/MappedInputManager.cpp:528–537` 的 `wasReleased(Back)` 同时包含物理按键和 `wasBackGesture()`；后者 `:453–472` 包含左侧右滑以及页面头部返回点击。不是底部上滑 Home 直接解锁：`activities/ActivityManager.cpp:555–564` 已屏蔽待机期间的 Home 手势。
- 修改前 `activities/apps/standby/StandbyActivity.cpp:503–511` 直接把该混合 Back 事件交给 `standbyShortcutEnabled`。全局返回手势开启时，触摸返回会沿按键路径离开待机，缺少独立的锁屏偏好。
- 新增 `standbySwipeUnlock`，默认 0；JSON 缺少此键时同样关闭，已有全局 Back/Home 偏好不被迁移或覆盖。保存为独立 JSON 键，不改二进制缓存格式。
- 入口为「设置 → 系统 → 手势 → 锁屏右滑解锁」，复用原列表开关及保存流程。开启后，仅从屏幕左侧向右滑动可离开当前待机，返回待机前页面；不强制跳首页。
- 手势几何复用 SDK 的逻辑方向／边缘判断，不依赖 `rickyGestureBack` 或 `rickyGestureHome`。其他方向和中央滑动不解锁。
- 锁屏按键 Back 路径排除触摸合成的 Back（包括旧页面残留返回点击区域），防止绕过新开关。原按键待机开关、侧电源键、锁屏 Home 快捷键保护及前光恢复不改。

仅 Plus 固定快照改动，没有新任务、延时或堆分配；新增一个 uint8_t 设置字段和一个静态列表行，布局沿用可滚动设置列表。中英标签走 I18n，主机检查确认新标签的全部中文字符已在六套相关内置字体区间内，无需改字库像素。深度休眠的硬件唤醒能力未改变；本轮 Plus 的 HAL 不进入仅 Read Pico 支持的该待机 light-sleep 路径，不把此开关宣传为给所有设备增加触控唤醒。

## 验证

`python3 tests/test_plus_standby_swipe_unlock.py` 编译实际 Standby loop、Back/Release 和解锁方法以及真实 SDK 边缘几何（ASan/UBSan）：

- 缺省关闭、旧 JSON 缺键关闭、开关保存/读取往返。
- 全局 Back/Home 和按键待机开关全部组合下，只有独立开关决定右滑解锁。
- 关闭时原返回手势不穿透；头部残留返回点击、反方向、其他边缘及中央滑动不解锁。
- 物理和 Plus 映射 Back 仍按既有按键偏好退出，横竖逻辑尺寸的边缘几何可用。

该主机测试不代替实机触控、按键、返回页面及重启后偏好持久化验收。新功能待上机确认，正式 OTA 尚未更新。
