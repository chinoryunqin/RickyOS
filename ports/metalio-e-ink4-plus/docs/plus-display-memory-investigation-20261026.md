## 已取得的证据

1. 最初电脑识别到 USB JTAG 设备，但收不到串口数据，连接芯片也失败。
   没有执行 Flash 写入。用户重新开机接线后，收到正式版本启动日志。
   “OS 能枚举调试设备”与“应用/芯片可通信”是两种证据，不能混同。
2. 原版固件这次能进入 USB 磁盘，主机识别到 RickyOS Metalio Plus MSC，
   16 GB SD 卡挂载为 FAT32。只读设置文件成功，约 50 ms；随后安全弹出成功。
   测试程序未拷入、删除或修改 SD 卡文件。OS 自身的挂载行为不由测试程序控制。
   **此前等待连接故障未在此次重启后的会话复现，不等于已修复间歇故障。**
3. 进入文件传输时：internal free=112491、largest=63488；
   DMA free=86051、largest=63488；PSRAM free=12706484 字节。
   切到 USB 前：internal=109571，DMA=83131，largest 仍为 63488。
   这一次没有观察到内部/DMA 分配失败，不能说 USB 一定是内存不够。
4. 插线阅读采到 52 次成功的普通阅读刷新与多次 GC16。
   稳定连续区段为 14 次普通刷新后 1 次 GC16，与每 15 页清屏相符。
   未见 `0x400`、line underrun、LCD first fault 或 TPS 上电失败。
   用户本次未看到明显逐渐变灰，但指出拔线使用时似乎会出现。
5. 测试过程中用户把阅读动效从关闭切到涟漪，因此两个阶段需分组，
   后续插线/拔线对照必须固定动效、抗锯齿、前光、全刷间隔、字体和书页。
6. 一次阅读进入/退出 free 从 112623 到 107251，最大块同为 63488；
   后续进入为 111691 / 51200。仅这些样本不能证明泄漏：字体等缓存可跨会话保留，
   比较必须在同一界面、相同暖缓存条件下重复，并分别看总空闲与最大连续块。

## 内存域和所有权

以下是源码中的有效载荷，分配器开销/任务控制块等需看运行时，不可简单相加。

| 对象 | 主要内存域 | 规模与寿命 |
|---|---|---|
| front/back 4-bit 与 8-bit 差分帧 | PSRAM | 合计 1,663,488 B，显示生命周期 |
| 应用 1-bit 帧 | 现有 facade | 103,968 B，不为动效再复制整帧 |
| 双供行队列 | INTERNAL | 2×128×304=77,824 B 数据；256 次逐项分配 |
| LCD bounce 双缓冲 | INTERNAL/DMA | 实机 4,880 B，另有描述符 |
| 双供行任务 | 内部任务栈 | 各 4096 B，另有控制对象 |
| 动效热窗口 | 静态高速 DRAM | 2304 B，避免运行时申请失败 |
| 每次动效相位表/延时格 | PSRAM | 41,156 B，两个供行者结束后归还 |
| TinyUSB MSC FIFO | 静态内部区 | 4096 B，不是普通 malloc 分配的 PSRAM 缓冲 |
| TinyUSB 任务 | 内部任务栈 | 4096 B，另有上下文/描述符 |

显示初始化实测内部占用 100588 B（约 98 KiB）。代码入口包括
`display/render.c:294-420`、`display/output_common/line_queue.c:18-40`、
`display/output_lcd/lcd_driver.c:813-848` 与 `display/ricky_native_turn.inc`。
不是所有 INTERNAL 内存都是高速 HP DRAM：S31 的 RTC RAM 也具有 INTERNAL 能力。
DMA 可用量是内部内存的子集，不能再加到内部空闲量上。

全局 `CONFIG_SPIRAM_MALLOC_RESERVE_INTERNAL=65536` 不是每个功能独享的预算。
`ALWAYSINTERNAL=2048` 改的是普通分配的偏好；明确 INTERNAL/DMA 的申请仍受能力约束。
因此不能用“还有十几 MB PSRAM”排除内部内存压力，也不能凭该阈值变化就断言它移动了 USB FIFO。

后续架构工作先基于暖缓存、USB/阅读/网络切换循环的实际峰值与最大块建立预算，
把可重建缓存明确放 PSRAM，把实时供行/中断数据保留高速内部区，
审查活动退出和失败回滚。当前不提高全局预留、不扩大供行缓冲、不移走 USB DMA 数据。

## 本轮诊断改动

### 修复 Plus 定时内存日志的错误门控

`upstream/src/main.cpp:1188-1200` 原先以 Arduino `Serial` 判断是否记录，
而 `upstream/lib/Logging/Logging.cpp:68-72` 的 Plus 实际走 IDF console。
修正为 Plus 独立启用原有 10 秒日志，并分别报告内部、DMA、PSRAM 的
free/minimum/largest。复用 HAL；没有新增堆缓冲。

### 显式诊断构建的离线记录

设置 `RICKYOS_PLUS_FIELD_DIAG=1` 才编译 `PlusFieldDiagnostics.cpp`。
普通构建不存在此记录函数、状态与文件写入。
依据现有 `BatteryMonitor::readPowerSnapshot()`、`epd_lcd_get_first_fault()`、
`epd_lcd_get_timing()` 和 `RenderLock::Mode::Try` 实现：

- 主循环每 5 秒尝试一次；绘屏锁繁忙直接跳过，不启动任务或唤醒定时器。
- USB 独占路径提前返回，记录器另外检查 USB 状态；绝不在 MSC 持卡期间访问文件系统。
- 仅追加 `/.crosspoint/plus-display-memory-v1.csv`，上限 128 KiB；到上限停止，
  不覆盖、不截断。打开、短写或关闭失败后本次启动停止记录。
- 512 B 栈行缓冲和少量静态计数；复用 HAL 文件对象的现有文件系统簿记。
  每次关闭文件，下一条带上次写入耗时，以便量化观察器开销。
- 记录原始 BQ 电压/电流及有效位、采样时 CPU 频率、充电器 0x1e 原值、
  上次 TPS 启动就绪状态、首个 LCD 故障、上次相位耗时、各内存域的 free/min/largest。

**限度**：BQ 是慢采样，采样 CPU 频率不是扫描中的频率，TPS 就绪是缓存状态，
相位统计是最近一次已完成刷新而非逐页事件。没有示波器不能由此排除瞬时压降，
也不能把 first fault=0 当作光学对比度合格。SD 采样本身也有开销；插线和拔线
必须使用同一诊断包，并核对 previous_write_ms。需要模拟供电测量时另行设计硬件测试。

构建使用打补丁的 IDF `9a97f6c54ec638111ce55cd36581b3c192f15207`。
本轮没有修改波形、驱动时间、充电参数、CPU 策略或内存分配阈值。

## 退出图书清理 ui3（2026-10-26）

用户初步反馈 ui2 暂时正常，但退出图书残影保留，希望全刷并释放内存。
`EpubReaderActivity::onExit` 原来的 cleanup 请求只编译到 Read Pico；Plus 的
主 Tab 动效因此可能用快速差分覆盖阅读页，保持未变化的灰色像素。
`ReaderActivity::onExit` 在所有 PSRAM 设备上保留可重建字体缓存。
