## 已修复：建立基准不再依赖绘制页面

修复前，实际 Plus 源码 `upstream/lib/hal/HalPowerManager.cpp:441-469`
只在页面调用百分比入口时取得遥测。估算器要求满电条件持续观察至少 180 秒，
相邻样本不超过 90 秒；静置不刷新或很慢翻页时可能始终无法建立基准。
完整证据和测量边界见 [原调查](plus-battery-investigation-20261022.md)。

以下文件相对 `ports/metalio-e-ink4-plus/firmware/rickyos-plus-1.2/`：

- `upstream/lib/hal/HalPowerManager.cpp:441-450` 新增 `pollBatteryWhileAwake()`。
  首次立即尝试，之后主循环每 30 秒最多发起一次尝试；复用原来的百分比入口、
  单采样者原子保护、5 秒底层采样限频、显示缓存和错误处理。
- `upstream/lib/hal/HalPowerManager.h` 仅在 Plus 配置下增加时间戳/已尝试标记和入口。
  两个标量，不增加堆分配、任务、定时器或唤醒源。
- `upstream/src/main.cpp:1104-1108` 在已经运行的主循环中调用，
  放在独占 SD/USB 存储分支返回之前：此采样走 I2C/NVS，不读取 SD。
  静态阅读、全屏待机以及 USB 存储界面均不需要绘制电量栏才能采样。
- 采样不请求 UI 更新，缓存待下次正常绘制显示。睡眠/关机期间不调用，
  阻塞或睡眠后的第一次循环仅尝试一次，不补采历史样本。
  一旦实际间隔超过 90 秒，资格证据仍由估算器按原规则重置。
- 页面读取与周期尝试复用同一个采样门和缓存，不能同时发起两个 HAL 电池读数。
  若恰逢其他调用占用，周期尝试不等待该采样者，下一周期再试。

满电电压/瞬时电流/平均电流条件、连续证据窗口、RCC 异常处理、NVS 检查点策略、
容量参考、后备电压公式、显示限速及硬件充电参数均未改变。
修复保证的是在主循环正常运行时有独立于绘制的采样机会；

### 建议分两阶段实现

第一阶段做 Plus 专用板级接口，只验证侧键/计时器唤醒。
仅在滑动解锁关闭的诊断条件下进入；滑动解锁开启时继续维持既有行为，
不把它静默降级为只能按键唤醒。Wi-Fi/Bluetooth、音频/录音、USB 活跃、
显示未完成、按键/触摸待处理时均推迟睡眠。

候选顺序：等待显示完成并关前光 → 通过原共享总线锁读取扩展器并区分/清理已知中断 →
确认按键释放、GPIO2 为高 → 配置 GPIO2 低电平与下一次表盘更新所需定时唤醒 →
再次检查输入以覆盖配置竞态 → 显式轻睡眠 → 无论失败或正常返回，清理本次唤醒配置，
恢复引脚/共享总线/输入轮询 → 由扩展器状态识别短按、长按、其他中断或计时器。
睡前不能持有 I2C 互斥锁跨过睡眠；不能用板级关机脉冲函数代替轻睡眠。
GPIO2 持续低、I2C 失败或休眠请求失败时退回正常循环，并限频重试，避免唤醒风暴。

第二阶段再加入 GPIO5 触摸唤醒与滑动解锁。
先证明“唤醒用的第一次滑动”可完整保留，再允许该设置下轻睡眠；
需覆盖快速点击、短滑动、持续按住、手指释放时机以及侧键/触摸同时到达。
若无法保留完整手势，则该设置下继续不睡眠，不让用户重复操作才能解锁。

首个候选优先保持已有外围供电状态，先验证 MCU 睡眠与唤醒；
后续再分别量测显示/音频/SD 等外围裁剪收益，不能一次套用厂商的深睡电源裁剪。
切断触摸电源后不可能继续依赖触摸唤醒；清理/恢复须覆盖每个失败出口。

未来实机验收应包括：侧键短按/长按与快速连按、计时器多轮、RTC/运动中断、
GPIO2 持续低、I2C 错误、首次滑动、前光恢复和连续睡眠后的阅读/SD/显示。
以独立电池侧积分比较静态图片待机、时钟待机和关机，确认进入/退出日志与电流一致。
不能仅以“不闪屏”或 API 返回成功作为低功耗验收。

## 以后允许设备验证时如何确认采样修复

1. 核对设备镜像身份后，在近满、合格电流条件下停留同一页面至少 4 分钟，不翻页、不触摸。
2. 记录真实样本及 `model`，确认采样持续发生、资格成立后切到 `model=2`；
   页面显示可等正常重绘，不以百分比 100% 替代基准证据。
3. 验证非合格电流不能建立基准；日志断档不直接等同实际采样断档。
4. 进入正式关机后确认采样停止。当前不启用 Plus 待机轻睡眠，待机内采样仍属已唤醒循环。
5. 对照原测量方案检查新增采样的电耗和 I2C 延迟。通过后再讨论准确度，
   不把这次离线编译/回归当成长期耗电验收。
