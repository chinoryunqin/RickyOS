# 书库与存储：用户选择收录范围（模拟器体验版）

## 范围与工作区

- Read Pico 共享实现：`/Users/rick/rickyos/wt-library-storage`，`codex/library-storage-sources`，基线 `6ec61ccd`（`private/codex/sync-plus-124`）。
- Plus 独立适配：`/Users/rick/rickyos/wt-plus-library-storage`，`codex/plus-library-storage-sources`，基线 `21382423`（Plus 1.2.4）。
- 不改其他工作区，不包含进行中的资源迁移／系统服务隔离实验。按用户要求交付至私有仓库 `chinoryunqin/RickyOS-dev` 的同名实验分支；不合并正式版、发布或刷机。

## 已实现

- 书库右上角 `＋ → 管理书库`：添加书籍、添加文件夹、刷新、管理收录来源。
- 添加文件夹时选择“仅当前目录”或“当前及子目录”。
- 存储中文件长按可“添加书籍”；直接打开文件不自动将其加入书库。
- 所有收录都是原路径引用，不搬动、不复制图书。
- 新增单本／目录只处理新选择的范围，其他已有记录通过索引顺序回放；重复添加不重复显示。
- 移出书库只修改索引和排除记录，不删除文件、缓存、阅读进度；刷新后不会偷偷重新加入。
- 移除来源只过滤已有目录记录，不重新枚举磁盘；保留其他来源／单本引用仍覆盖的书。
- 导入页面有进度和取消；取消／失败保留上一份有效索引，并回退本次来源编辑。退出等待工作线程释放存储句柄，不强杀读卡任务。
- 旧安装首次使用时，仅将旧目录索引快照为有限的历史引用，不把 SD 根目录自动登记为扫描源。
- “全部／在读／未读”保留。在书库中不再为未读文件计算内容哈希。
- 进入书库和启动固件均不自动重建整卡索引；目录设置或脏标记不会触发隐式全盘扫描。
- 翻页只读取一页记录和已有封面缓存，缺失封面沿用现有排版封面，不在绘制中解压 EPUB 或生成缩略图。
- 存储首次进入只读历史统计，显示“未统计”而不是误报 SD 卡不可用；手动刷新统计不会重建书库。
- 文件夹行不再为了显示“几项”而枚举其子目录。
- 手动自建分类，独立于“全部／在读／未读”：书库点“全部分类”筛选／新建，长按分类重命名／删除。
- 一本书可以同时属于多个分类；书籍长按“设置分类”，或“批量管理”跨页选择后统一归类。
- 批量归类对未触碰的分类保留各书原状态；返回取消，不提交本次归类。混合选择显示“部分已选”。
- 删除分类有二次确认，只删分类关系，不删书。名称支持现有设备拼音输入。

## 存储与内存约束

- 原 CLIX1 索引布局不变；未修改正文、分区、阅读进度格式。
- 来源配置：`/.crosspoint/library-sources.v1`，魔数 `LSR1`、长度界限、FNV 校验、临时文件和备份恢复。
- 旧目录引用：`/.crosspoint/library-legacy.idx`，只复制原索引，不复制图书。
- 规则从 8 项开始按需、可失败地扩容：通常约 2 KB，最多 128 项（目录、单本引用、排除记录共享上限）；目录中的书不消耗逐本来源槽。
- 移除来源时历史引用匹配最多额外使用 512 B 位图；不在内存再放一份全书路径列表。
- 原索引上限 4096 本、递归深度 5 保持不变。本轮不是无上限图书数据库。
- 分类：`/.crosspoint/library-categories.v1`，独立 `LCT1` 格式，16 个稳定槽、每名最多 48 字节、最多 4096 个成员指纹。CLIX 重建／排序不会改变分类。
- 分类成员引用完整路径指纹，与现有索引身份一致；外部移动／改名后属于新路径，不承诺跨改名自动迁移。分类操作本身不移动文件。
- 分类编辑以固定 10 字节磁盘记录流式合并，不加载全书路径。批量选择位图 512 B；显式归类选中指纹最多 32 KB，可失败分配。
- 筛选只临时分配所选分类的指纹（每项 8 B，最多 32 KB）和原有行映射（最多 8 KB）；绘制／翻页不重载分类或枚举 SD。
- 书库工具统一使用一个处理入口，保持基础界面的 6 个处理槽预算，不扩大所有页面的常驻内存。

### 尚不能由模拟器确认

真实卡上的耗时、卡损坏时的阻塞、实际灰阶残影和功耗必须真机验证，未声称已有性能百分比提升。
当前文件浏览器仍保留“当前目录名称列表”，没有在本轮改成万级单层目录的分页数据库；超大单层目录仍是后续需测量的风险。
未生成的 EPUB 缩略图暂用排版封面，不能把“缓存封面绘制”表述成所有封面已自动生成。
强制断电可能留下新的来源计划与旧索引；它不会触发根目录扫描，用户可显式刷新所选来源完成恢复。

## 基线模拟器兼容修复

共享基线原生构建暴露了三类问题：无矢量字体时持有不完整的 `TtfEpdFont`、板型宏在阅读配置／解析器头中取值过早、固定桌面 DNS 桩的 `start()` 返回值与固件不一致。分别以条件成员、显式板型头和维护的模拟器适配脚本修正；没有更换 SDK 或修改显示波形。
