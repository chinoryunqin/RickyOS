# 书库与存储 第二版设计（几千本书场景）· 2026-10-21

基于 `codex/library-storage-sources`（47b407c4）/ `codex/plus-library-storage-sources`（36e35848）的初版。
目标用户：卡里几千本书（含整套漫画），要求不卡、找得到、能分类。

## 1. 初版评估

保留（方向正确，继续用）：

- 不再隐式全盘扫描：书库只收录用户指定的来源（文件夹 / 当前及子目录 / 单本 / 排除）。
- 原路径引用，不搬文件；移出书库不删文件。
- 导入可取消，失败保留旧索引；配置文件带校验、`.tmp/.bak` 安装。
- 手动分类（多分类、批量归类）。

仍然存在的问题：

| # | 问题 | 现状 |
|---|---|---|
| 1 | 上限 | CLX1 最多 4096 本，递归深度 5。“好几千本”会直接碰顶 |
| 2 | 翻不到 | 封面网格每页 6 本：3000 本 = 500 页，没有跳转 |
| 3 | 搜索慢 | `applyFilter` 按排序行逐本 `readRecord` + `readAuthor`：每本 1~2 次随机 SD 读，几千本是秒级；每改一次关键词重来一遍 |
| 4 | 搜索难输入 | 只能匹配汉字/字母原文；墨水屏上打汉字慢，不能用拼音首字母 |
| 5 | 分类靠手 | 只有手动分类、16 个上限。几千本逐本归类不现实；用户已有的文件夹结构没有被当作分类利用 |
| 6 | 漫画/系列 | 一套 30 卷占 30 个格子，没有聚合，也不知道下一卷 |
| 7 | 刷新 | 刷新来源 = 重新枚举该来源全部文件；传书（Wi-Fi/USB）后要用户手动刷新才出现 |
| 8 | 身份 | 书的身份是完整路径：移动/改名后分类、阅读进度（缓存目录按路径哈希）都断开 |
| 9 | 存储页 | 与书库入口重叠（“书籍”格子）；文件浏览器缓存整目录名称，超大单层目录有风险；没有多选、排序、空间清理 |

另：初版所有性能数字来自桌面模拟器，**没有真机数据**。第二版第一步先在 Read Pico 和 Plus 上用 3000 本的 SD 卡实测导入、搜索、翻页、存储进入的耗时。

## 2. 数据层

### 2.1 书目索引 CLX v3（替换 CLX1，版本号变化即自动重建）

- 上限 4096 → **16384** 本（排列表仍是 u16；排序键 14 B/本，16384 本 ≈ 224 KB，放 PSRAM，两台设备都有余量）。
- 记录仍为 128 B，不改定长寻址；在名称区新增字段：
  - `series` 系列名、`volume` 卷序号（u16，0 = 无）。
    来源优先级：OPF `belongs-to-collection` + `group-position` → `calibre:series` / `calibre:series_index` → `dc:series` + 书名/文件名里的“卷04 / 第4卷 / Vol.4 / 04”。
  - `sourceId`：属于哪个收录来源（u8），用于“文件夹书架”和来源刷新。
- 新增排列：系列序（系列名 → 卷号），最近添加序已存在。

### 2.2 检索文件 `library.find`（新增，随索引一起生成）

每本一条紧凑记录，**按记录序号顺序存放**：

```
[u16 ordinal][u8 len][书名 fold][0][作者 fold][0][拼音首字母][0][系列 fold]
```

- 进入搜索时一次性顺序读入 PSRAM（3000 本约 150–250 KB），之后每次输入都在内存里过滤，目标 <50 ms，可以边输边出结果。
- 内存不足时退回现在的逐本读取（保留现有代码路径）。

### 2.3 拼音首字母

- 用现有输入法字典 `PinyinDictionary.h`（音节 → 汉字）在建索引时反查每个汉字的声母；多音字保留全部声母（如“长” → c/z），匹配时任意一种都算。
- 只在建索引时计算，不常驻反查表。
- 例：输入 `jtyss` 命中《金田一37歲事件簿》，`st` 命中《三体》，`lx` 命中作者“鲁迅”。

### 2.4 增量登记（传书即入库）

- Wi-Fi 传书、USB 传书、浏览器上传完成时，已经知道新写入的文件路径：如果落在某个已收录来源下，**直接登记这几本**（解析元数据、追加记录、重排），不扫描目录。
- 落在未收录目录：记入“新传入的书”待处理列表（见 4.3），不自动加入。
- 刷新来源只用于用户在电脑上直接改卡的情况；刷新时只枚举文件名，已有记录按（路径、大小、修改时间）复用，只为新文件解析元数据（初版已有复用逻辑，保留）。

### 2.5 移动 / 改名识别

- 刷新时，若一条旧记录的路径消失，同时出现一条新路径，且**文件名、大小、修改时间都相同**，视为移动：迁移分类成员、阅读进度与缓存目录（`epub_<pathhash>` 改名）、阅读统计别名。
- 不满足条件时按新书处理（现状行为）。

### 2.6 分类 LCT2

- 上限 16 → 64 个分类；成员上限随索引到 16384。
- 新增“**规则分类**”：一个分类可以绑定若干收录文件夹，该文件夹下的书（包括以后新加入的）自动属于该分类；手动加入/移出的单本记录优先于规则。
- 格式沿用 LCT1 的校验/备份机制，版本号 `LCT2`，读到 LCT1 自动迁移。

## 3. 书库界面

### 3.1 顶部常驻搜索

- 搜索框常驻顶栏，点开即用拼音键盘；支持汉字、拼音首字母、作者、系列。
- 结果实时刷新，结果页同样可切换排序和视图。

### 3.2 两种视图

- **封面网格**（现状，每页 6 本）：适合几十到几百本。
- **列表**（新增，每页约 12 行：书名、作者 / 系列卷号、阅读进度）：适合几千本。
- 视图选择按书架记住（例如“全部”用列表、某个分类用网格）。

### 3.3 快速定位

- 按书名/作者排序时，右侧一条**字母索引条**（A–Z、#），点字母跳到拼音首字母对应的页；物理键设备在页码处长按弹出字母选择。
- 页码处可直接输入页数跳转。

### 3.4 书架维度

顶部筛选从“全部 / 在读 / 未读 + 全部分类”调整为两层：

1. 书架：**全部 · 文件夹 · 分类 · 系列 · 作者**
   - 文件夹：每个收录来源就是一个书架，可改显示名、可隐藏，不需要手动归类就有分类效果。
   - 系列：自动聚合，一套书显示为一个封面（“金田一37歲事件簿 · 12 卷”），点进去按卷号排列。
   - 作者：按作者分组（初版已有作者排序和分组键）。
2. 状态：全部 / 在读 / 未读 / 已读完（保留现有逻辑）。

### 3.5 系列阅读

- 读完一卷，书末菜单提供“下一卷”（同系列、卷号 +1）。
- 系列封面显示已读到第几卷。

### 3.6 排序

最近阅读 / 最近添加 / 书名 / 作者 / 系列（卷号）。

## 4. 收录流程

### 4.1 首次使用

不自动全盘。进入书库时如果还没有任何来源，列出卡上**顶层**文件夹（只读一层目录，不进入子目录）供勾选，例如 `/books`、`/漫画`、`/Kindle`，默认推荐勾选含书最多的常见目录名；用户确认后才导入。

### 4.2 添加方式

- 书库 `＋`：添加文件夹（当前目录 / 含子目录）、添加单本、管理来源。
- 存储里：文件或文件夹长按 → 加入书库。
- 传书：上传到已收录目录自动入库（2.4）。

### 4.3 “新传入的书”

- 记录最近通过传书写入、但不在任何收录来源下的文件（最多 200 条，不扫描）。
- 书库顶部出现一条提示“有 N 本新书未加入书库”，可一键加入或忽略。

### 4.4 来源管理页

每个来源显示：路径、书数、上次更新时间、是否含子目录、绑定的分类；可单独刷新、改显示名、隐藏、移除。

## 5. 存储页：从“入口”改成“文件管理 + 空间管理”

定位：**书库管读书，存储管文件**。去掉存储页里与书库重复的“书籍”格子。

### 5.1 首屏

- 容量条：总容量 / 已用，分段显示 书籍、字体、图片、阅读缓存、其他。统计结果缓存，手动刷新时才重新计算（初版已改为不自动统计）。
- **清理**：阅读缓存（按书列出，可只清已删除书籍的残留缓存）、封面缩略图、诊断日志。
- 快捷位置：各收录文件夹、下载、字体、图片、传书收件箱。
- 传书入口（Wi-Fi 传书、USB 传书）放在这一页。

### 5.2 文件浏览器

- **分页读取目录**：只读当前页需要的目录项，不再缓存整个目录的名称列表；2000 个文件的单层目录也能直接进入。
- 排序：名称 / 修改时间 / 大小；目录内按名称或拼音首字母过滤。
- 标记：已收录的书显示“已在书库”，已收录的文件夹显示“书架”。
- **多选**：移动、删除、加入书库、设置分类；新建文件夹。
- 移动/改名在设备上完成时，同步更新索引、分类、进度（直接知道新旧路径，不依赖 2.5 的推断）。

## 6. 分阶段

| 阶段 | 内容 | 解决 |
|---|---|---|
| P0 | 真机测量：3000 本卡在 Pico、Plus 上的导入、搜索、翻页、进入存储耗时 | 有数据再定优先级 |
| P1 | CLX v3（16384 本）、`library.find` + 拼音首字母搜索、列表视图、字母索引条、传书自动入库 | 卡、找不到 |
| P2 | 文件夹书架、系列识别与聚合、下一卷、规则分类 LCT2 | 分类 |
| P3 | 存储页：分页目录、多选、空间清理、新传入的书 | 存储实用 |
| P4 | 设备内移动/改名同步、电脑上移动的识别（2.5） | 进度不丢 |

每阶段：主机测试 + 两台设备真机验收；Plus 由共享实现导出（初版的 `export_library_storage_changes.py` 流程）。

## 7. 待定

1. 分类上限 64 是否够；规则分类是否需要（还是只做“文件夹书架”就够）。
2. 首次使用是否推荐常见目录名（`/books`、`/漫画`），还是完全让用户自己选。
3. 系列识别是否也要用文件名规则（会有误判，例如书名里本身带数字）；可只在 OPF 没有系列信息时启用，并允许用户在系列页手动拆分。
4. 存储页的删除是否需要“回收站”（删除先移到 `/.trash`，7 天后清空）。
