# Plus 静态待机候选（2026-10-22）

## 决策和证据

转向原厂 2.0.76 的静态待机路线；暂停 80/40 MHz 清醒待机对比，时钟浅睡最后处理。

- 原厂 `main/boards/common/power_policy/power_hw.cc:293–382` 每次最多一片浅睡；入睡时停 SD、TPS、屏总线，释放加速度计共享中断、屏蔽其他键，只允许 GPIO2/P17 和计时器唤醒。
- 原厂在每次返回时仍恢复按键、电轨、SD、USB、屏总线；静态 Park 的关键是**不提交新画面**，不是每个计时器返回都完全不恢复外设。
- 原厂 `main/boards/common/sensor/sc7a20h.cc:105–137` 当前源码的静默配置为 AOI1/CTRL3/CTRL5=0，CTRL1=0x10，CTRL6=0x03（低有效开漏）；本候选保存原值并在返回时恢复，额外检查读回。
- RickyOS 上轮失败是首次计时器返回后重绘，随后记录 `ROW_NOT_READY / row426 / producer0`。静态路线绕开该计时器重绘触发点；**侧键退出后的第一次重绘仍需实机验证**，不能据离线测试宣布白屏根因修复。
- 3 mA 是厂商给出的基准，尚未在本候选或这台 RickyOS Plus 上测得。

## 实现边界

显式配置 `RICKYOS_PLUS_STANDBY_SLEEP=1`、`RICKYOS_PLUS_STATIC_STANDBY=1`，诊断时另开 `RICKYOS_PLUS_STANDBY_DIAG=1`。普通版本继续默认禁用实验浅睡。此配置不与清醒 40/80 MHz 对比混用。

- `StandbyActivity::tryLightSleep` 只接受已经完成首帧的静态待机；选图页、时钟、滑动解锁、蓝牙、录音、前光、Wi-Fi/同步均阻止入睡。时钟保持清醒，不偷偷改用户面板或设置。
- 一片不超过 60 秒，Timer 分支不运行 `processFaceTick`、不请求刷新；按键仍按原有一次手势一次动作逻辑退出/长按处理。普通待机自动关机期限由活动循环继续判断。
- RenderLock 和刷新完成屏障覆盖硬件交接；Storage 独占租约覆盖关机、浅睡和恢复，其他任务的文件访问等待租约释放。
- 只读、绝对路径小于 320 字节的普通文件可保存位置并关闭，唤醒后以只读重开，检查长度并恢复位置。写句柄、目录、匿名迭代句柄、未知路径、重命名后未重开的句柄阻止入睡。已知路径的删除、重命名、替换、写入会使对应恢复路径失效，防止重开到不同文件。
- 同步块设备成功后才停 SDK SDMMC；SD 总线进入 GPIO 低电平并锁存。没有调用板级旧 VFS 挂载器；恢复始终用同一个 SDK/SdFat 管理器。
- TPS 睡眠、屏总线释放、SC7A20H 静默、仅留 P17、外设电轨 P5→P14 关闭；输出锁存和方向寄存器须读回匹配。
- 返回先锁存 P17，清理自有 EXT1/timer/RTC mux，再恢复键、电轨 P14→P5、SD 引脚、SDK 挂载和文件位置、IMU、USB，最后检查 LCD 重建。每个中止路径也执行已应用步骤的恢复。
- 恢复失败或显示首错后，禁止后续睡眠直到重启。GPIO2 是共享中断线，已释放且无法确认 P17 的脉冲不伪造为短按。

**未修改充电寄存器、充电参数、电量容量模型、分区表或 OTA 元数据。**

新增真实成对寻址模型的生产函数测试：复现旧六字节读法的错误、正常 park/restore、每个寄存器不匹配、每对 I2C 读取失败、锁失败。新增 RAM 逐项状态 `static park`（SD、IMU、按键、输入、GPIO2、方向校验）和 `static restore`（方向、引脚、SD、IMU），避免以后只有聚合失败而无法区分具体环节。
