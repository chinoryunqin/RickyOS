## 1. 百分比为何可能仍回退旧模型

`UP/lib/hal/HalPowerManager.cpp:441-469` 仅在调用 `getBatteryPercentage()` 且
显示层允许采样时读取一次。实际调用点集中在 `UP/src/components/themes/BaseTheme.cpp`
和 `UP/src/util/HeaderDateUtils.cpp`；主循环没有周期调用该百分比入口。
`UP/src/main.cpp:1346-1354` 也明确避免在阅读/全屏待机中因 USB 状态变化强制重绘。
“最短 5 秒”是调用限频，不能解读为后台采样周期。

`PL/include/PlusBatteryEstimator.h:178-188,214-228` 的满电资格要求：
电压至少 4290mV，瞬时和平均电流均为 −5～40mA，至少 4 次有效观察，跨度至少 180 秒；
相邻观察超过 90 秒则重新开始。无效遥测也会打断资格。
如果只开机看一次，或超过 90 秒才翻一次有电量栏的页面，电压再高也不能仅靠时间经过建立基准。
不能通过放宽满电条件、直接增加 UI 刷新或限制掉数来证明准确。

离线脚本直接编译生产估算器，输入始终为 **假设** 的 4366mV、+12mA、有效 RCC：

| 合成采样安排 | 首次建立基准 | 末次 model |
|---|---:|---:|
| 只有开机一次 | 不建立 | 0 |
| 每 60 秒一次 | 180 秒 | 2 |
| 每 90 秒一次 | 270 秒（还需满足 4 次） | 2 |
| 每 120 秒一次，观察 10 分钟 | 不建立 | 0 |
| 每 180 秒一次，观察 12 分钟 | 不建立 | 0 |
| 每 60 秒一次，但电流为 −30mA | 不建立满电基准 | 0 |

这些是资格条件回放，输入不代表真实充电曲线或放电过程。
`model=0` 为未标定电压后备、`1` 为 1A 带载曲线首次锚定、`2` 为累计耗电模型。
`BAT source` 是另一个枚举，不能把 `source=2` 误读成 `model=2`。

1.2.5 启动证据：发布工作树
`ports/metalio-e-ink4-plus/.local/device-installations/plus125-20261021/boot.log:102-103`
为 `4366mV current=12/1 avg=12/1 rcc=65531/1 op=0x00b4/1 model=0`，显示 100%。
这只证明开机当次没有已使用的有效基准，不能证明当天一直 model=0，
也不能把当次 +12mA 当成整机阅读功耗。

`PL/include/PlusBattery.h:6-8` 的后备模型是 3300–4330mV 线性插值：
约 10.3mV 对应 1 个百分点（取整前）。负载压降和拔线电压变化可能直接影响估算。
厂商 1A 表同源偏差约 20.66 个百分点，不能外推成几十 mA 阅读负载的真实误差。
原表、已生成图和分析仍保留在原位置，不重复绘制、不上传原表。

## 2. 图片静止为何仍可能持续耗电

证据链：

1. `UP/src/activities/apps/standby/StandbyActivity.h:23-25` 的 `preventAutoSleep()` 恒为 true；
   `UP/src/main.cpp:1250` 因此跳过通用自动休眠计时。
2. `StandbyActivity.cpp:448-470` 的轻睡眠必须通过 `canStandbyLightSleep()`。
3. `UP/lib/hal/HalPowerManager.cpp:342-354` 对非 Read Pico 要求是 Xteink 设备、
   存在直接电源 GPIO 和保持电源引脚。
4. `UP/lib/hal/HalGPIO.cpp:399-403` 的 Xteink 判断不包括 Plus；
   `PL/include/BoardConfig.h:2107-2121` 将 Plus 电源键设为扩展器输入，直接 GPIO 为 −1。
   主机执行生产判断方法，Plus 条件返回 false。
5. `StandbyActivity.cpp:559-577` 只抑制静态图片重复显示；
   `:545-553` 仍执行页面循环，并可在**单独设置的待机自动关机时间**到达后关机。
   不应把通用休眠被挡理解为永不自动关机。

结论是当前 Plus 不走这条显式待机轻睡眠路径；不能由此给出整机 mA，
也不能排除其他系统省电机制。`HalPowerManager.cpp:223-247` 仍可空闲降频，
`HalPowerManager.h:41-46` 为 PSRAM 目标配置 80MHz，实际转换成功需运行证据。
当前构建是否有其他自动睡眠机制也应以对应构建配置和运行记录核实。

已有主动清理，不宜无证据重写：

- `StandbyActivity.cpp:137-144` 停录音、音频输出、触觉反馈并关前光；
  `:409-417` 校时结束关闭 Wi-Fi 并释放驱动。
- `UP/src/main.cpp:245-250` 在触摸设备退出 Wi-Fi 会话时关 Wi-Fi；
  `:447-466` 正式休眠/关机前也关闭 Wi-Fi、前光、显示和存储。
- `FW/components/rickyos_application/port/PlusBoard.cpp:24-35` 将关机交给板级脉冲；
  `UP/freeink-sdk/libs/hardware/PowerManager/src/PowerManager.cpp:186-195` 在回调返回后等待。
  “脉冲已发出”日志本身不能证明供电已切断，关机后电流必须单独测。

## 3. 先判断计量链是否可信

TI BQ27220 TRM Rev.A 表 2-1、§2.8、§2.17、§2.27 支持当前只读寄存器选择：
电流 0x0C、平均电流 0x14、RCC 0x22（mAh）、运行状态 0x3A。
RCC 放电增加、充电减少，FC 时可能归零；忽略/计入自放电的配置也影响其含义。
电流死区和累计死区见 §4.9.10–11，因此低耗电时读到 0 不能证明零耗电。
官方来源：[TI 技术参考手册](https://www.ti.com/lit/ug/sluubd4/sluubd4.pdf)。

仍需检查实物电流比例、零点、计量覆盖的电源路径，以及 RCC 能否跟随独立电流积分。
厂商标称 2000mAh、台架 1A 窗口 1870.7mAh，与原始 Design/FCC/RM 3000mAh
是三类信息；不能互相替代，更不能据此改写 BQ 或充电配置。

累计模型以 1870.7mAh 为参考，约 18.707mAh 对应 1 个百分点。
这只是算法的换算关系，不代表该设备在现有充电电压、温度、老化与负载下的可用容量。

## 4. 可执行测量顺序

本表是**未来操作方案**，本次未执行。先确认设备已从其他任务释放，再约定采集方式。
正式 1.2.5 可先做手动观察；完整结论需要电池侧独立测量和遥测证据。

### 第一步：分开“建立基准”与“测功耗”

先记录固件/镜像身份、充电线状态、环境温度、同一本已排版的本地文本书、
前光亮度/色温、Wi-Fi/Bluetooth、音频/录音状态和待机自动关机设置。
不要一边导入书库、一边给电量做对照；书籍、字体、SD 卡在各组保持相同。

充电末段可用既有页面每 30–60 秒触发一次读取，持续至少 4 分钟，
以实际 `model=2` 为建立基准的证据；不以 UI 100% 为证据。
电流/电压不符合条件则记录失败原因，不把这组判为已满电标定。
该步骤含页面操作和 USB 连接，**不得用于声称待机/阅读功耗**。
若需接入日志读取，必须另行确认设备归属及串口操作授权。

之后拔掉供电线并记录拔线时刻。分组功耗测试建议在约 40–80% 的中段电量、
相近电压与温度下进行；避免满电尾端/低电量区的非线性混入组间差异。
不会为凑数据要求放到保护关机。

### 第二步：测量真实能量，而不是只记百分比

- 优先用合适的电池侧电流/能量记录仪，记录 mAh、Wh 和峰值/持续时间；
  接入、拆机和接线仅在后续明确安排后实施，本次不接硬件。
- 独立仪器应覆盖关机静态电流并保留短刷新脉冲的电荷积分；
  启用积分前确认量程、零点、采样/积分带宽和串联压降。
- USB 口电流表测到的是输入侧用电与充电的混合量，不能当成拔线电池电流。
  USB 也可能改变休眠条件；不用插着供电线的结果代替电池供电测量。
- 暂时只有 BQ 时，可先做 RCC 对照筛查，但标明“同一计量链，非独立验证”。
  短期、全程明确放电且无复位时才用 `ΔRCC / 小时` 估算平均 mA；
  重启、FC 清零、可疑回绕、充放电切换或无效字段均分段，不能盲算。
  假设最低 1mAh 的量化步长，要比较小于 1mAh 的差异时延长窗口或用独立仪器。

### 第三步：一次只改一个条件

各组先稳定约 2–5 分钟，再积分；A→B→A 回测至少一次，记录前后电压/温度。
表中时间是起步窗口；低于仪器分辨率/重复性时延长，不把“无变化”当作零。

| 组别 | 操作与时长 | 对照与能回答的问题 |
|---|---|---|
| R0 静态阅读 | 同页停留，前光/Wi-Fi/Bluetooth 关闭，30 分钟；确保不进入待机 | 唤醒空闲底耗；无法独立确认 MCU 与各外围的占比 |
| R1 常规翻页 | 同书已排版章节，每 30 秒翻页，30 分钟 | 与 R0 等时比较；计算增量 mAh/翻页，包含渲染、SD 与显示，不冒充纯屏幕功耗 |
| R2 全刷条件 | 同内容/次数，固定另一全刷频率，30 分钟 | 与 R1 比较；记录快速/全刷次数，不混用图片书/文本书 |
| L 前光 | 静态阅读，0→25→50→100→0，每档 15 分钟、固定色温 | 前光增量；若整档电压/温度漂移明显则重测 |
| W Wi-Fi | 关网→已连接静置→固定一次下载→退回阅读；静置各 15–30 分钟 | 分开常驻、传输与退出后残留；记录字节、耗时、失败/重试、信号；不沿用 2026-10-16 的 RF 设置数值作耗电证据 |
| S0 静态图片待机 | 一张本地图，关前光和网络，60 分钟；设定关机时间覆盖窗口并记录原值 | 不刷新条件下底耗，与 R0/真正关机对比；之后恢复设置 |
| S1 时钟待机 | 同条件换时钟，60 分钟，统计实际刷新次数 | 与 S0 等时比较，分离周期刷新/唤醒代价；不能直接认定差值全是屏幕 |
| O 正式关机 | 正常用户关机，独立仪器观察 60 分钟，必要时延长到 8 小时 | 验证外部供电确实关闭，区分关机未完成与电芯/常供电回路耗电 |

R0 为避免自动待机，临时延长超时后应恢复；不要靠持续触摸来保持亮机。
W 组首次下载包含关联/TLS 成本，应另记连续下载成本；每次结束确认回到 R0 电流范围。
Bluetooth、音频等本轮作为固定关闭条件，只有底耗仍异常才开单独组定位。
长待机不靠周期串口轮询或页面刷新取样；仪器持续积分，设备遥测只记进入/退出快照。

## 5. 数据格式、判定及诊断缺口

每个区间保存：`run_id, firmware_sha, condition, wall_time_start/end, device_boot_id,
monotonic_ms, usb_present, temperature, mv, current_mA, average_mA,
rcc, op, all_valid_flags, model, estimate_percent, shown_percent,
frontlight_brightness/warmth, wifi_mode, bytes/retries, page_turns,
fast/full_refresh_count, sleep_entry/wake_reason, external_mAh/Wh`。
设备不支持的字段保留缺失，不能填零或假值。跨重启用外部时间对齐，
不要拼接不同日志时间基准当成单一单调时钟。

当前日志节流在 `BatteryMonitor.cpp:585-599` 及 `HalPowerManager.cpp:461-466`：
最多每分钟打印一次，且前提是有人读取。**相邻日志间隔不能用来证明中间没有采样**。
短期可通过受控页面操作验证资格；要完整定位，需要未来诊断候选补充有效采样序号、
前次采样间隔、满电资格样本数/跨度、基准建立/丢失原因、RCC 异常和检查点恢复/保存结果。
目前日志不足以可靠还原这些内部状态。

| 观测组合 | 可以得出的结论 | 仍不能得出的结论 |
|---|---|---|
| 显示明显下降，独立积分变化小，电压负载变化，model=0 | 优先调查电压后备/基准缺失 | 不能按电压直接反推出真实 SOC |
| RCC 与独立积分同向相符，某功能组增量重复出现 | 该使用条件有可重复能耗增量 | 没有产品基准就不能宣布绝对耗电“超标” |
| 独立积分明显、RCC 不跟随 | 调查计量比例/路径/死区/计数状态 | 不能靠换曲线修复计量链 |
| S0 电流远高于正式关机，且确认无显式轻睡眠 | 支持持续唤醒/外围常开为排查方向 | 尚不能把总差值归给 MCU 或屏幕某一个部件 |
| 外部仪器确认关机低耗，但恢复后百分比跳变 | 优先调查基准恢复/电压回弹/计数复位 | 不能由百分比跳变声称一夜掉了对应容量 |

比较时报告每组 mAh/h、Wh/h、重复范围及仪器误差；翻页再报告增量 mAh/次。
先约定相对于重复性与测量不确定度可分辨的差异，再判断异常。
准确度需独立容量/电荷参照及多段放电验证；没有独立参照时只报告一致性，不报“误差小于 X%”。

## 6. 后续修正的边界与验证

采样问题依据见第 1 节：可考虑在**已经唤醒的主循环**中有界采样，
脱离绘制，不强制刷屏、不为采样新增唤醒。先评估 I2C 共享锁、并发缓存和增量电耗，
保持满电资格、RCC 校验及硬件充电参数。候选必须证明静置近满可建立基准、
不合格电流不能建立、进入休眠后不额外唤醒，且整机能耗未被采集显著改变。

待机问题依据见第 2 节：不能只把 Plus 加进 Xteink 白名单或给电源键编造 GPIO。
必须先核对 S31 支持的唤醒源、扩展器/触摸中断接线和保持状态；
若支持滑动解锁，还须验证睡眠后首次手势/侧键、无唤醒风暴、I2C 恢复及前光状态。
正式关机仅凭脉冲日志无法验收，要以断电/电流下降证据确认。

本次没有改固件，故不更新补丁/清单、不构建新镜像。
后续源码修正仅在 Plus 电量分支完成，且必须同时记录 `upstream-plus.patch`
与 `source-manifest.json`，从全新恢复源码复验，不能只改仓库根源码或恢复目录。
新的设备采集、刷机、推送、发布均不由本报告自动授权。

现有 Plus 代码已从 BQ27220 读取电压、瞬时/平均电流、原始 SOC 和累计量，

不能把“读取芯片”直接等同为“百分比准确”，也不因此写入 PMU、BQ 或充电参数。

“关机彻底断电”暂解释为主控/外设负载供电应被硬件切断，而不只是 MCU 睡眠；
是否仍保留电量计/充电电路，以及通过电源控制器脉冲还是其他方法切断，要厂商给出型号与时序。
当前代码会调用板级电源脉冲，但此前没有关机后独立电流实测，不能声称硬断电已验收。

这条信息将后续验证分为独立目标：整机待机电池侧电流、关机负载断电、电量读数可信度。
它不能单独解释轻睡眠白屏或 USB 失联；两轮失败候选仍默认禁用，设备维持已恢复的原版 1.2.5。
