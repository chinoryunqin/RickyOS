# 普通版 Metalio E-Ink 4：Plus 功能移植

日期：2026-10-29。工作分支 `codex/metalio-eink4-1.2.11`，以 Plus 分支 `codex/plus-1.2.11` 的 `2973acbb` 为基线。目标是普通版 ESP32-S3 / 16 MB Flash / 8 MB PSRAM / SSD1677 800×480；不能使用 Plus 的 S31 固件。

## 来源与构建

Plus 的实际应用位于 `ports/metalio-e-ink4-plus/firmware/rickyos-plus-1.2/upstream`，而非分支根目录。使用还原脚本验证了 2842 个文件和 285 项适配后，将应用 src、lib、test、scripts、data 移入根目录，保留 Plus 的原始还原包。普通版 BSP、SPI 屏幕驱动及专用 FAST LUT 来自此前 1.2.6 dev3 适配。

还原包漏记了 ReadingCard、ReadingExcerpt 的四个源文件；已从同一提交的现有 Plus 工作区补齐。其余应用源码已逐个比对，无差异。`metalio-eink4-plus-feature-source.json` 记录供体文件与补齐文件的 SHA-256；其中 files 记录移植输入，并不表示修改后的输出散列。

构建命令：`pio run -e rickyos_metalio_eink4`。当前已刷入版本 `1.2.11-metalio-dev3`，保留此前双 6.25 MiB OTA 分区和原有 S3 Arduino 3.3.11 / IDF 5.5.5 工具链。增加 IDF 5 的 SHA-256 兼容层，普通版只编译已适配的屏幕后端。scripts/configure_metalio_eink4.py 会核对八份压缩字体的来源散列，缺失/变更时运行从 Plus 移植的无损压缩生成器；生成器逐像素检查输出。

## 已知问题和设备边界

此前普通版 dev3 在暖复位后曾出现 I2C SDA/SCL 同时低、SD 初始化失败；用户完全断电后反馈“好像正常了”。这仍不足以证明暖启动问题已修复，本轮保留该问题并需要真机复验。

本轮已用 ROM 读取确认普通版芯片为 ESP32-S3 rev0.2、8 MB PSRAM，MAC 为 `10:20:BA:6D:6C:CC`。同时可见另一个设备；它被其他进程用于 Plus 的刷写，后续仅操作普通版端口。原普通版的 ROM MAC / USB 标识为 `10:20:BA:6D:6C:CC`。本轮电脑枚举为 `1C:29:04:D0:2A:50`；用户说明一直连接普通版，因此只记录身份不一致，不能据此推断用户换机。刷写前必须读取 ROM 芯片型号、MAC 并核对目标板，不能仅凭端口名写入。

原厂 2.0.62 的 16 MiB 完整备份已保存且验证，SHA-256 为 `9ad0fe4aad54d5b38c0d1162bca8df2489ed2dca1a7da2fa8edbc9d54195f271`。

当前普通版启动日志显示运行 Pudding，而非此前 dev3。本轮重新读取 16,777,216 字节完整 Flash，并通过 ROM verify-flash 摘要核验；备份 SHA-256：`e646a9633c3d75c80960527aa8e5e9296f5f109f2472a85a9da181d96af46524`。Pudding 分区为 recovery @0x10000 / 1 MiB 与 pudding @0x110000 / 0xEF0000；本次使用 RickyOS 标准双 OTA 布局，保留 @0x9000 / 0x5000 的 NVS。安装器在写入前比对设备 MAC、原分区表、NVS 和 OTA 数据，在写入后校验全部目标段及 NVS。

本开发版未接入普通版正式 OTA 发布通道，现有更新器会拒绝其他设备的固件。SD 卡本地更新仍执行普通版 board tag 核验。

## 本轮启动结果

第一版 dev：刷写全部四段并校验，NVS 保持不变；SD 挂载成功，进入 InxRecent，但运行后 I2C 持续返回 ESP_ERR_INVALID_STATE。

第二版 dev2：将普通版板级供电/I2C 初始化提前，与触控、按键、震动初始化分开；后者延至屏幕初始化之后。仅重写选中 app0，MD5 校验通过，分区表和 OTA 选择未变。启动日志确认普通版板级初始化成功、SDMMC 挂载成功、版本正确，屏幕后扩展器读数成功且 SDA/SCL 均为 HIGH，随后进入 InxRecent。连续运行 60 秒，I2C 错误计数为 0；内部空闲 RAM 156,960 字节，PSRAM 空闲 7,786,792 字节，五次周期采样保持不变。用户交互确认仍待反馈。这个对照支持保留当前初始化顺序，但不能据此宣称所有暖启动条件都已解决。

普通版 IMU 尚未启用，倾斜翻页本轮不作为已适配功能；启动的 SDK IMU not found 对应这一能力边界。NVS namespace NOT_FOUND 是新设置命名空间不存在，并未影响 SD 挂载或首页进入。

串口 SCREENSHOT 命令已取得 48,000 字节原生帧缓冲；截图当时为 RickyOS 品牌页（启动/待机画面），不能将这张截图当作首页的视觉验收证据。实际玻璃显示方向、触控与侧键等待用户确认。

第三版 dev3（当前已刷入）：立即截帧发现 dev2 的 Plus 竖屏首页统计与最近书籍区域在小屏上相互挤压，因此短内容视口切换到供体原有的测量式布局，并减少个人区与页脚的占高。保留头像/个人入口、继续阅读、最近书籍、今日阅读和连续阅读统计；仍可点统计入口打开完整页面。重新构建、刷入 app0 并校验成功，分区表和 OTA 数据保持不变。启动后 SD/I2C 正常，6 秒时的首屏截帧核对通过，内容没有侵入底部导航。实际屏幕方向、触控和侧键待用户确认。
