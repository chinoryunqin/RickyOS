## Read Pico 传书“内存不足”（1.2.2 就有，本分支修复）

真机复现：打开文件传输 / 加入网络 / 创建热点提示内存不足。不是同步引入的：1.2.2 正式版
同样流程只多 1～2 KB 余量。串口诊断 `CMD:NETCYCLE`（`-DRICKYOS_NETCYCLE_DIAG=1` 构建，
`src/diag/NetCycleDiag.cpp`）自动循环热点与加入网络并记录内部内存：

| 步骤（刚开机第一次开热点） | 修复前 | 修复后 |
|---|---|---|
| 启动传书服务前 | 16.2 KB，被 16 KB 门槛拒绝 | 29.6 KB |
| 服务启动后 | — | 25.4 KB |
| 用过网络后回首页 | 47 KB（第一次用网常驻约 23 KB） | 56 KB |
| 第二次开热点，服务前 | 15.5 KB，被拒 | 28.7 KB |
| 加入网络（真实连接），服务前 / 后 | — | 31 KB / 26 KB |

改动（仅 Read Pico）：mDNS 任务栈放 PSRAM；热点 DNS 的 UDP 任务栈 4096 → 2560（峰值约 0.9 KB）；
Arduino 网络事件任务栈 4096 → 2560（峰值约 1.2 KB）。发送缓冲减到 4 块无效（本来就在 PSRAM），已撤回。
另加保险：启动传书时若仍被内存门槛拒绝，自动重启一次并直接回到所选模式（加入网络或热点）；
传输过程中的内存不足仍照旧提示，不会中途重启。

## 验证

- Read Pico：5,890,480 B 起（网络修复版另计），主机测试通过；真机整机安装后启动到首页。
- EEGO A4：6,074,832 B，超过在线升级上限 6,029,312 B 约 45 KB，发版前要处理。
